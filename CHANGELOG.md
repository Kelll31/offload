# Изменения

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [SemVer](https://semver.org/lang/ru/).
Планы — в [ROADMAP.md](ROADMAP.md).

## [Не выпущено]

### Добавлено

- **Автоподключение Claude.** Claude Code и Claude Desktop (в том числе MSIX-версия), установленные до или после Offload,
  подключаются сами: первый прогон через 20 секунд после старта, затем раз в 15 минут. Только там, где записи `offload` нет;
  чужая, устаревшая и нечитаемая запись автоматически не трогается, запись идёт через `ConfigFile.Edit` (резервная копия,
  атомарно). Для Claude Code ставятся навык и разрешения на чтение (как в мастере). Одно объединённое уведомление на прогон.
  Не действует в режиме разработчика и из копии не из папки установки; выключается настройкой «Подключать Claude автоматически и
  следить за подключениями к IDE» (мастер и «Интеграции»).
- **Проверка подключения после записи.** `IntegrationVerifier` заново читает конфиг как IDE и запускает команду из записи
  (`initialize` + `tools/list`), с повтором до трёх раз (2/5/10 с) на медленный первый запуск и антивирус. Работает в
  автоподключении, в мастере (итог «Подключено» с числом инструментов и временем) и при подключении на странице «Интеграции».
- **Понятные причины сбоев** (`FailureKind`): нет или занят или повреждён файл настроек IDE, нет exe, запуск заблокирован,
  сервер не стартовал, посторонний текст в stdout, таймаут — с указанием, что делать.
- **Отказы запоминаются** (`declinedIntegrations`): снятая галочка в мастере и «Отключить» на странице «Интеграции» не
  возвращаются автоподключением; явное «Подключить» отказ снимает. Список подключений после удаления с сохранением данных
  очищается, отказы остаются.
- Метка «Подключена автоматически» и итог последней проверки на странице «Интеграции»; в подсказке значка трея —
  «Claude: подключён» / «Claude: требует внимания».
- **Новый облик.** Бренд-палитра «Индиго» с градиентом акцента, рисованные скруглённые кнопки (основная — с градиентом),
  переключатели в духе Windows 11 вместо флажков, карточки со скруглением 12 px и мягкой тенью, выделенная карточка сервера,
  шапка страницы со значком раздела и «таблетками» состояния сервера и Claude, заголовки разделов с цветной меткой, новая
  боковая панель (бренд с версией, выделение акцентом, карточка состояния), плитки со значком в круге, столбцы графика
  с градиентом, скруглённые углы окна и рамка оттенка акцента в Windows 11.
- **Палитра команд (Ctrl+K):** нечёткий поиск по разделам и действиям — запустить/остановить сервер, проверить и подключить
  Claude, сменить тему, мастер настройки, выход.
- **Центр уведомлений:** раздел «Уведомления» со всеми уведомлениями сеанса (в том числе не показанными), счётчик
  непрочитанных в навигации, переход в раздел по щелчку; Ctrl+Shift+N.
- **Тихие часы:** в заданный промежуток (например, 22:00–08:00) всплывающие уведомления не показываются, остаются в центре.
- **Глобальная горячая клавиша Ctrl+Alt+O** открывает Offload из любой программы (выключается в «Настройках»).
- **Справка по сочетаниям клавиш (F1).**
- **Карточка «Claude» на странице «Состояние»:** Claude Code и Claude Desktop — установлен ли, подключён ли (автоматически
  или вручную), итог и время последней проверки; кнопки «Проверить сейчас» и «Подключить».
- **Ежедневная проверка подключений:** раз в сутки Offload запускает сервер по записи в каждой подключённой программе и
  сообщает, только если подключение сломалось или снова заработало.
- **Автоподключение других IDE по выбору:** Cursor, Windsurf, VS Code и другие найденные клиенты можно отметить на странице
  «Интеграции» — они подключаются по тем же правилам, что и Claude.
- **Восстановление настроек IDE из резервной копии** («Интеграции» → «Резервные копии…»): список копий, просмотр и
  восстановление; текущий файл перед этим тоже сохраняется.
- **Меню «Claude» в трее:** состояние, «Проверить подключение», «Подключить Claude сейчас», «Открыть „Интеграции“».
- **Тренды в плитках:** экономия и вызовы за сегодня сравниваются со средним за прошлую неделю («+35 %», «как обычно»).
- **Экономия за сегодня в подсказке значка трея.**
- **Схема «Как акцент Windows»** — цвет берётся из персонализации Windows и меняется вместе с ней.
- **Новые схемы «Аврора» и «Графит»** (тёмные) и отдельная «Синяя (Windows)» — прежний акцент по умолчанию.
- **Экспорт и импорт настроек** («Настройки» → «Перенос настроек»): только внешний вид и параметры сервера и инструментов;
  ключи, токены, пути, подключения к IDE и параметры безопасности не сохраняются и при импорте не меняются, перед применением
  показывается список изменений.

### Изменено

- В настройки IDE прописывается путь **установленной** копии Offload (если она есть, существует и не старше запущенной), а не
  запущенного exe: путь не меняется при обновлении и переезде портативной копии.
- Установщик: при тихой установке или обновлении (`/VERYSILENT`, winget) трей запускается в фоне — настроенный Offload сам
  подключит Claude без мастера. Установщик по-прежнему не пишет в конфиги IDE.

## [1.0.3] — 2026-09-27

### Добавлено

- **Автоподбор параметров llama-server** («Сервер» → «Автоподбор параметров»): покоординатный перебор `--n-cpu-moe`, `-ub/-b`,
  flash attention, типа KV-кэша, `-sm layer/row` (несколько видеокарт) и MTP с замером скорости; оценка — время типичного
  запроса (4000 токенов промпта + 400 генерации), победитель замеряется повторно и должен быть быстрее хотя бы на 3 %. Контекст
  не меняется, бюджет — 12 проб и 20 минут. Профиль хранится для пары «модель × оборудование» (`server.tunedProfiles`) и
  действует, пока совпадают настройки сервера; флаги из «Доп. аргументов» важнее; если запуск с профилем не удался, профиль
  сбрасывается. При отмене и сбое сервер запускается с прежними параметрами.
- **Несколько видеокарт:** устройства llama.cpp берутся из `llama-server --list-devices`, модель раскладывается по подходящим
  картам одного бэкенда (`--device`, `--tensor-split` по свободной видеопамяти, `--main-gpu` — самая большая, `-sm layer`);
  `FitCalculator` считает по сумме карт с буфером вычислений на каждую. Встроенная графика рядом с дискретной и карты меньше
  2 ГБ не используются. Настройка «Видеокарты: все подходящие / только основная» (`server.gpuSelection`).
- **Удалённый сервер:** ноутбук пользуется моделью, которую раздаёт Offload на мощном ПК. На ПК — «Доступ из сети» (по умолчанию
  выключен): llama-server слушает выбранный адрес только с отдельным сетевым ключом (`olan-…`, DPAPI), вспомогательные
  серверы остаются на `127.0.0.1`. На ноутбуке — «Удалённый сервер»: адрес и ключ (DPAPI), проверка подключения (модель,
  контекст, задержка); трей не запускает свой llama-server и следит за удалённым, MCP-сервер и OpenCode ходят к нему, контекст
  берётся из `/props`, `local_status` показывает адрес и задержку. В мастере можно не скачивать модель. Модель угроз дополнена.
- **`local_pr_ready`** — готовность ветки к PR одним вызовом: вердикт READY / READY WITH WARNINGS / NOT READY, блокеры
  (конфликты с базой через `git merge-tree`, упавшие сборка и тесты, секреты, маркеры конфликтов), предупреждения (TODO и
  отладочный вывод в добавленных строках, большие файлы, находки ревью моделью) и черновик PR.
- **`local_debug`** — отладка одним вызовом: воспроизведение командой (из белого списка; если не задана — по имени упавшего
  теста), разбор ошибок и стека, история изменений и «подозрительный» коммит, гипотеза первопричины, исправление агентом
  в песочнице со слиянием только после прохождения команды, повторный прогон и связанные тесты; `fix=false` — только диагноз;
  может работать в фоне.
- **Гонка агентов:** параметр `race` (1–4) у `local_agent_task` и `local_solve` — несколько агентов с разными стратегиями
  решают задачу в своих песочницах от одного снимка, вливается лучший прошедший проверку кандидат (ревью, раунды исправлений,
  размер diff, при близких оценках — судья-модель); diff остальных — ресурсы `offload://jobs/<id>/race/<буква>`.
- **Кэш результатов модели:** ответы `local_ask_files`, `local_review_diff`, `local_summarize_log`, `local_commit_message`
  и шаги модели в `local_find_context` по ключу из хэшей входных данных, модели и параметров; с моделью эмбеддингов попадают
  и перефразированные вопросы. SQLite в папке данных, по проекту, 50 МБ / 14 дней; параметр `fresh` у `local_ask_files`
  и `local_review_diff`, статистика попаданий в `local_status`, флажок в разделе «Промпт».
- **Автоматическая память проекта:** уроки задач агента, прошедших проверку после исправлений, и причины падений
  `local_verify` из-за окружения сохраняются в `local_memory` с пометкой `auto` (до 200 записей, без дублей и секретов);
  релевантные заметки добавляются в задание локальному агенту.
- **Автодополнение в IDE (FIM):** роль модели «Автодополнение», в каталоге — Qwen2.5-Coder 1.5B и 3B (Q8_0, ggml-org).
  Отдельный сервер на `127.0.0.1:8012` (или следующем свободном порту) работает, пока автодополнение включено, со своим
  сторожем; режим «только процессор», если рядом с основной моделью не помещается. Для Continue блок автодополнения
  пишется в `~/.continue/models/offload-autocomplete.yaml` (и убирается при выключении и удалении программы), для llama.vscode —
  адрес, ключ и готовый фрагмент настроек.
- **Модели с Hugging Face:** «Модели» → «Найти на Hugging Face…» — поиск GGUF-репозиториев, кванты с размером, оценкой
  «поместится ли» по заголовку GGUF, прочитанному диапазонными запросами (не больше 32 МБ), и рекомендуемым квантом; ревизия
  закрепляется, SHA-256 обязателен, разбитые на части GGUF — одна модель. Найденные модели хранятся в
  `catalog\huggingface.json` и помечены «не проверено мейнтейнером».
- `local_impact`: тесты, близкие к изменению по смыслу (векторы), — отдельным списком с пометкой semantic и полем
  `semantic` в структурированном ответе; `run_tests` их не запускает.

### Изменено

- Inno Setup закреплён на 7.1.0: скрипт установщика отказывается собираться другой версией, CI ставит её с официального
  релиза с проверкой SHA-256, `build.ps1` берёт путь из переменной `ISCC` и предпочитает Inno Setup 7. Раньше CI собирал
  предустановленной версией 6, а локально — 7, и ошибка совместимости была видна только на CI.

### Исправлено

- **Безопасность:** git в чужом репозитории мог выполнить команды из его `.git/config`. `local_review_diff`,
  `local_commit_message`, `local_impact`, `local_git_history`, `local_edit_files`, песочница агента и отслеживание изменений
  OpenCode запускали `git diff`/`status`/`log -p`/`checkout`, а те — фильтры clean/smudge, textconv, внешний diff и (в
  отслеживании изменений) fsmonitor из конфигурации репозитория. Теперь каждый вызов git гасит такие драйверы из областей
  репозитория и всегда отключает fsmonitor, хуки, внешний diff и проверку подписей (`GitSafety`).
- `UsageRecorder.FlushAsync` мог вернуться раньше, чем записанные задачи уходили из очереди (нестабильный тест на CI).

## [1.0.2] — 2026-09-27

### Добавлено

- «Что нового» после обновления: уведомление при первом запуске новой версии и раздел в «О программе» (текст — из заметок
  к выпуску, встроенных в exe; тест не даёт выпустить версию без них).
- `local_find_context`: связанные тесты, близкие к задаче по смыслу (векторы), вместе с найденными по именам — помечены
  «(semantic)».
- `local_memory recall`: переранжирование реранкером (роль rerank), в том числе без модели эмбеддингов.

### Исправлено

- Установка и самообновление через установщик падали с «DeleteFile: код 5 / Отказано в доступе», пока открыта IDE:
  MCP-серверы `Offload.exe --mcp` держали exe. Установщик теперь завершает процессы Offload из папки установки
  (`CloseApplications=force` и завершение перед заменой файлов); так же — при удалении программы.
- Удаление программы убирало автозапуск Windows, даже если он указывал на другую копию Offload.

## [1.0.1] — 2026-09-27

### Добавлено

- Сторож зависания llama-server: периодическая проверка `/health` запущенного процесса и перезапуск после трёх неответов подряд.
- Настройка «Подробный журнал» и переменная `OFFLOAD_LOG_LEVEL`.
- Сохранение размера и положения окна и последнего раздела; щелчок по уведомлению открывает связанный раздел.
- Предложение удалить файл старого кванта после загрузки нового.
- Режим разработчика (`OFFLOAD_DEV=1` или запуск из папки сборки): копия не перенастраивает автозапуск и IDE на себя.
- Установщик на английском языке (выбирается по языку Windows) и корректная тихая установка и удаление (`/VERYSILENT`)
  для winget и scoop.
- Подпись `Offload.exe` и установщика в сборке (`build.ps1 -Sign`), включается при наличии сертификата.
- CI: проверка «тег = версия», дымовая проверка MCP опубликованного exe, подтверждение происхождения сборки (build provenance),
  CodeQL, Dependabot, анализаторы кода (предупреждения — ошибки), Central Package Management; права workflow сокращены
  до чтения, actions закреплены по SHA, секреты подписи — только в окружении релиза.
- Документы: `SECURITY.md`, модель угроз (`docs/threat-model.md`), `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`,
  `THIRD-PARTY-NOTICES.md`, английский README, шаблоны issue и PR, `ROADMAP.md`.
- Проект тестов `Offload.App.Tests`.
- **Самообновление Offload** из GitHub Releases: SHA-256 из `SHA256SUMS.txt`, проверка подписи того же издателя (если текущий
  exe подписан), повторная проверка перед запуском; для установленной и портативной копии.
- **Справедливая очередь GPU:** короткие интерактивные вызовы приоритетнее агента; при нескольких слотах один всегда свободен
  для интерактивных вызовов; `local_status` показывает, кто занимает слоты, а подвал — время ожидания.
- **Размещение «Авто»:** контекст и выгрузка экспертов MoE при запуске считаются той же оценкой, что показывает интерфейс,
  с учётом видеопамяти, занятой другими программами (NVIDIA — nvidia-smi, AMD/Intel — счётчики Windows).
- Рекомендация числа параллельных слотов (страница «Сервер» и мастер) и замер скорости модели.
- **llama.cpp:** хранение двух предыдущих сборок, переключение и закрепление версии, автоматический откат, если новая сборка
  не прошла проверку или не запустила сервер по своей вине; поле каталога `minLlamaBuild`; сборки OpenVINO и OpenCL Adreno
  (выбор вручную).
- **Доктор интеграций:** проверка рукопожатия MCP для каждой IDE, известные подводные камни, время последнего обращения.
- Автоматическое исправление пути к Offload в конфигах IDE после перемещения программы; о прочих расхождениях — уведомление
  и кнопка «Восстановить».
- Инструкции по делегированию для Codex (`~/.codex/AGENTS.md`) и Gemini CLI (`~/.gemini/GEMINI.md`) — управляемая секция.
- OpenCode: проверенная версия с зашитыми SHA-256 (канал stable), канал latest, откат к предыдущей версии.
- Пакет диагностики (zip с журналами и настройками, ключи замаскированы) и заполненный шаблон issue.
- Карточка «Ждём первого обращения из IDE» с тестовым запросом к модели.
- Дашборд: выбор периода, ошибки по инструментам, экспорт CSV.
- Доступность: имена и роли рисованных элементов для экранного диктора, автоматическая схема высокого контраста.
- **Безопасность MCP:** маскирование секретов по содержимому (индекс кода, чтение файлов для модели, ответы инструментов);
  необязательная защита файлов сборки (`Mcp.ProtectBuildFiles`, параметр `allow_build_files`); `npx` — только локальные пакеты;
  внутренние команды `local_dependency_check` через фиксированный белый список; межпроцессная блокировка памяти проекта;
  версия протокола IPC.

- **Протокол MCP:** структурированные ответы (`outputSchema` + `structuredContent`) у `local_verify`, `local_diagnostics`,
  `local_impact`, `local_status`; ресурсы `offload://runs/{id}`, `offload://jobs/{id}/diff`, `offload://project/map`,
  `offload://memory` и ссылки на них вместо обрезки; прогресс с общим числом шагов; подтверждения пользователя (elicitation)
  для рискованного слияния, отката поверх правок и разовой команды проверки вне белого списка; автодополнение аргументов
  промптов; мульти-корни в ревизии протокола 2026-07-28.
- **Постоянный индекс кода** (SQLite в папке данных): инкрементальное обновление, общий для всех IDE; граф вызовов
  для `callers`/`callees`; кэш карты проекта; ранжирование `local_find_context` по BM25.
- **C# разбирается Roslyn** (точные объявления, ссылки вне строк и комментариев, rename с учётом перегрузок); исправлены
  эвристики для других языков (многострочные сигнатуры, docstring Python, шаблонные строки JS, методы Go, `Foo::bar` в C++).
- **Роли моделей:** быстрая модель для коротких задач, модели эмбеддингов и реранка (отдельные серверы llama-server по
  требованию); в каталоге — Qwen3-Embedding-0.6B и BGE Reranker v2-m3.
- **Фоновые задачи агента выполняются в трее** и переживают закрытие IDE; прерванные задачи видны как `interrupted`,
  их можно перезапустить (`local_job action=retry`); уведомление по завершении.
- **MCP по HTTP** (`Offload.exe --mcp-http`, только loopback, токен) и **подключение Claude Code в WSL**.
- **Удалённый каталог моделей** с подписью Ed25519 (включится, когда мейнтейнер опубликует ключ); токен Hugging Face
  (DPAPI), зеркала и прокси в настройках; загрузка больших файлов в несколько соединений.
- **Единое разрешение инструментов записи** на странице «Интеграции»: один пункт для Claude Code, Cline, Roo Code, Kiro
  и Gemini CLI (`trust`); состояние читается из файлов клиентов, новые инструменты записи — только повторным согласием.
- Миграции `config.json` по `SchemaVersion` (копия прежнего файла в backups перед записью; файл более новой версии не понижается).

### Изменено

- Выгрузка модели при простое — только механизмом сна llama.cpp (`--sleep-idle-seconds`); состояние сна видно в трее
  и на странице «Состояние».
- Число параллельных запросов — до 8, единый предел для интерфейса, аргументов llama-server и очереди MCP.
- `local_status` показывает контекст на один запрос и общий KV-кэш слотов отдельно; бюджеты частей для модели считаются
  по доле слота.
- Статистика: прошлые месяцы уходят в архив `usage-ГГГГ-ММ.jsonl`, страница «Состояние» дочитывает только новые записи.
- Резервные копии конфигов: имена до миллисекунд без перезаписи, хранится 10 последних копий на файл (и всегда — самая первая),
  копии старше 30 дней удаляются, кроме трёх последних.
- Журнал фоновой задачи агента — в папке задачи (`jobs/<id>/opencode.log`).
- Правообладатель и издатель приведены к одному имени.
- Ключ API llama-server передаётся переменной окружения `LLAMA_API_KEY`, а не в командной строке.
- Экономия токенов считается и для инструментов без модели (поиск, символы, карта проекта, проверки); токены — токенизатором
  модели; для агента — по реальному объёму diff.
- `LlamaServer.cs` разделён на файлы по ответственности; общие помощники MCP вынесены в одно место.

### Исправлено

- Удаление программы оставляло в `~/.claude` правило и субагента Offload.
- Ручные правки `config.json` затирались при следующем изменении настроек; повреждённый файл больше не заменяется
  значениями по умолчанию (прежние настройки сохраняются, файл остаётся для исправления).
- Регистрация в глобальном конфиге OpenCode теряла комментарии JSONC и обходила общую защиту правки конфигов.
- Недоступный для чтения `config.json` (занят другой программой, нет доступа) перезаписывался значениями по умолчанию;
  теперь он не трогается, а чтение повторяется при следующем обращении.
- Программа не находила свою установку: ключ удаления в реестре — «{GUID_is1» (без закрывающей скобки), а искался
  «{GUID}_is1». Из-за этого не работали защита от второй копии, режим обновления через установщик и поиск прежней
  установки в самом установщике.
- Портативная или dev-копия могла переписать автозапуск Windows на себя; теперь путь автозапуска меняется, только если
  прежний exe больше не существует (программу переместили).
- Любая ошибка со словом «context» принималась за переполнение контекста; в англоязычных ошибках MCP был русский текст.
- Проверка в песочнице агента получала полный таймаут задачи вместо оставшегося времени.
- Ротация `mcp.log` при нескольких MCP-процессах могла терять строки.
- Страница «Состояние» запускала `nvidia-smi` каждые 3 секунды.

### Безопасность

- llama.cpp и OpenCode без известной SHA-256 больше не устанавливаются (обход — `OFFLOAD_ALLOW_UNVERIFIED=1`).
- MCP по HTTP: корни закрепляются при запуске (`--root`), выполнение кода и запись по HTTP выключены без `--allow-exec`,
  случайный порт для каждого пользователя, тело запроса читается только после проверки токена.
- «Разрешить один раз» в `local_verify` — только для программ из белого списка, никогда для интерпретаторов и системных
  утилит-загрузчиков; в диалоге показывается итоговая команда; по HTTP отключено.
- WSL: запись и чтение через символические ссылки дистрибутива проверяются изнутри WSL (`realpath`).
- Серверы ролей моделей используются только по адресу, полученному от трея, с проверкой псевдонима.
- Фоновые задачи в трее выполняются с окружением IDE (PATH, venv, nvm…), без переменных с секретами.
- Адреса файлов релизов (llama.cpp, OpenCode, Offload) принимаются только с `github.com/<репозиторий>/releases/download/…`;
  зеркала проверяются и при чтении настроек; пароль прокси маскируется в пакете диагностики.
- Удалённый каталог защищён от повтора старой версии (`max-version`, подписанное поле `expires`).
- Постоянный индекс кода хранит только данные после маскирования секретов.
