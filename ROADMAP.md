> Состояние на сентябрь 2026 года, версия `1.0.3`. Документ живой: пункты перемещаются между этапами по мере работы,
> выполненные отмечаются `[x]` и уходят в CHANGELOG. Идеи и сообщения об ошибках — в [Issues](https://github.com/Kelll31/offload/issues).

**Как читать**

- Этапы идут по порядку, но внутри этапа пункты независимы — их можно брать параллельно.
- Приоритет: **P0** — баг или риск доверия, чинить первым; **P1** — главное в этапе; **P2** — желательно; **P3** — если останется время.
- Объём: **S** — до дня, **M** — несколько дней, **L** — неделя и больше или нужен отдельный дизайн (ADR).
- Ссылки на файлы — на текущий `main`; номера строк могут уплыть.

## 2. Принципы, которые не меняются

Каждый пункт ниже проверяется на соответствие этим инвариантам. Ослаблять их нельзя даже ради функции.

- **stdout MCP-процесса — только JSON-RPC.** `--mcp` разбирается в `Program.Main` до WinForms.
- **Файлы — только через `PathGuard`, команды — только через `VerifyCommand`.** Новые внутренние команды тоже проходят белый список.
- **Конфиги IDE — только через `IntegrationEnvironment` + `ConfigFile.Edit`**: бэкап, атомарная запись, комментарии сохраняются.
- **llama-server — на `127.0.0.1` с ключом API, загрузки — с SHA-256.**
- **Никаких прав администратора, Docker, WSL, Python, Node.js** для пользователя. Один exe.
- **Облачная модель решает, локальная делает.** Архитектура, отладка, безопасность и финальная проверка остаются за облаком; локальная модель берёт объёмное и проверяемое.
- **Приватность по умолчанию.** Никакой телеметрии без явного согласия, код пользователя не покидает машину.

## 5. Этап 1.2 — пропускная способность: параллельность и несколько моделей

Проблема видна на практике. При `Parallel = 1` пять субагентов Claude Code, обращающихся к `local_ask_files` одновременно, ждали по
24 → 47 → 85 → 122 с: очередь `GpuQueue` выстраивает их друг за другом. А `local_agent_task` держит единственный слот GPU до 90 минут,
и в это время все остальные вызовы из всех IDE стоят.

### 5.1 Параллельность по умолчанию

- [x] **P1 · M — Подбор `Parallel` в мастере и на странице «Сервер».** `FitCalculator` оценивает KV-кэш на слот (у гибридных моделей
  с DeltaNet он маленький) и предлагает 2–4 слота, если хватает видеопамяти. Показывать компромисс: «3 слота × 64K, VRAM 23,8/24 ГБ».
- [x] **P1 · M — Справедливая очередь GPU.** Короткие чтения (`ask_files`, `summarize_log`, `commit_message`) — приоритетнее агента.
  Агент не держит слот всё время работы, а берёт его на время каждого запроса к модели; при `Parallel ≥ 2` один слот резервируется
  под интерактивные вызовы.
- [x] **P1 · S — Прозрачность очереди:** `local_status` показывает, кто занимает слоты (инструмент, клиент, сколько ждёт); в ответ
  инструмента добавляется «ждал в очереди N с»; в `UsageRecord` пишется время ожидания.
- [ ] **P2 · M — Параллельные запуски OpenCode.** Сейчас один мьютекс `RunQueueLock` на весь профиль. Отдельный `XDG_DATA_HOME` на запуск
  и параллельность в пределах свободных слотов.

### 5.2 Несколько моделей и маршрутизация

- [x] **P1 · L — Роли моделей: `fast` / `quality` / `agent` / `embed`.** *(роли quality/fast/embed/rerank, вспомогательные серверы по требованию, маршрутизация по инструменту)* Сейчас один `ActiveModelId`, один процесс, alias зашит как
  `"offload"`. Нужно: второй экземпляр `LlamaServerProcess` на своём порту (или router-режим llama-server), alias на модель,
  `ActiveModelIds` по ролям, выбор в `LocalModel` по типу инструмента. Например, `commit_message`, `summarize_log` и
  `find_context` (расширение запроса и реранк) — на 4B/9B; `ask_files` и ревью — на 27B или MoE; агент — на лучшую модель.
  Мастер предлагает пару по бюджету VRAM + RAM.
- [ ] **P2 · M — «Профили нагрузки»** в трее: «Качество» (одна большая модель, MTP), «Параллельно» (N слотов), «Экономия видеопамяти»
  (MoE с выгрузкой экспертов). Переключение одним кликом, без ручной настройки флагов.

### 5.3 Настройка под железо

- [x] **P1 · M — Применять результат `FitCalculator` при запуске.** Сейчас `FitResult.CpuMoeLayers/GpuLayers/ContextSize` используются
  только в UI, а запуск отдаёт размещение `--fit` с другим контекстом, так что показанное расходится с фактическим. Режим «Авто»
  передаёт `-c`, `--n-cpu-moe`, `-ngl`; после старта из журнала читаются фактические буферы, поправочный коэффициент сохраняется для
  пары «модель × железо».

## 6. Этап 1.3 — понимание кода: постоянный индекс, tree-sitter, эмбеддинги

  Сейчас каждый вызов заново запускает `git ls-files` и `stat` по всем файлам, кэш свой в каждом процессе и при переполнении
  сбрасывается целиком.
- [x] **P1 · M — `callers`/`callees` как запрос к графу.** Сейчас каждый узел на глубине до 4 заново проходит весь индекс через

## 10. Сквозные направления

### 10.1 Безопасность

- [x] **P0 · M — Секреты по содержимому, а не только по имени файла.** Сейчас строки подключения в `appsettings.json` и токены в конфигах

## 12. Бэклог идей

Без приоритета и обязательств. Кандидаты в этапы после обсуждения в Issues.

- **Режим «сравнить с облаком»:** на выборке задач сравнить ответ локальной модели и Claude — калибровка того, что можно доверять
  локальной модели.
- **Самообучающиеся подсказки:** если облачная модель регулярно перепроверяет или переделывает ответы конкретного инструмента,
  показывать это в статистике («`ask_files` на этой модели — 30 % повторных запросов»).
- **Шаблоны задач `local_solve`** от сообщества (миграция .NET, добавление эндпоинта, покрытие тестами модуля).
- **Сессионная память контекста:** `find_context` помнит, что уже отдавал в этой сессии, и не отдаёт повторно.
- **Командный сервер:** один мощный ПК с Offload обслуживает несколько разработчиков по LAN (Streamable HTTP + ключи на пользователя +
  квоты слотов).
- **Плагины инструментов:** пользовательские `local_*` на базе промпт-шаблона и белого списка команд, без пересборки.
- **Интеграция с CI:** `Offload --mcp` в self-hosted runner для первичного ревью PR локальной моделью.
- **Экспорт статистики экономии** для отчёта команде: «сколько облачных токенов и денег сэкономлено за месяц».

## 13. Что мы сознательно не делаем

- **Облачные модели внутри Offload.** Offload — про локальную модель; облако — это IDE пользователя.
- **Свой форк llama.cpp или OpenCode.** Только официальные релизы, закреплённые и проверенные.
- **Телеметрию без явного согласия.** Диагностика — только пакетом, который пользователь отправляет сам.
- **Права администратора для обычной работы.** Исключение — VC++ Redistributable через UAC по запросу.
- **Ослабление `PathGuard`/`VerifyCommand` ради удобства.** Расширение белого списка — только осознанно, с тестом в `SecurityRegressionTests`.
- **Docker, WSL, Python, Node.js как обязательные зависимости** для пользователя.

## 14. Решения и открытые вопросы

**Принято (сентябрь 2026):**

- **Постоянный индекс кода — SQLite** (`Microsoft.Data.Sqlite`): надёжный конкурентный доступ из нескольких MCP-процессов,
  запросы к графу вызовов; цена — около 2 МБ нативной библиотеки в exe.
- **Точный разбор — Roslyn для C#**, для остальных языков — исправленные эвристики (без tree-sitter: нативные грамматики
  в single-file exe — слишком большой риск).
- **Удалённые каталоги моделей и интеграций — JSON с подписью Ed25519**; открытый ключ зашит в exe, закрытый хранит мейнтейнер.
- **Lock-файлы NuGet не используются** — только Central Package Management с транзитивным закреплением.
- **Режим разработчика** (`OFFLOAD_DEV=1` или запуск из `bin\Debug|Release`) — копия не перенастраивает автозапуск и IDE на себя.

**Открытые вопросы (кандидаты в ADR):**

| Вопрос | Варианты | От чего зависит |
|---|---|---|
| Несколько моделей: как запускать | несколько процессов llama-server / router-режим llama-server | стабильность router-режима, расход VRAM, сложность `ServerController` |
| Где живут фоновые задачи | в трее через IPC / отдельный сервис-процесс | что если трей закрыт; обновление exe во время задачи |
| Агентный бэкенд по умолчанию | OpenCode / Crush / Goose / Codex CLI | качество на локальных моделях, headless-режим, стабильность формата событий |
| Подпись кода | Azure Trusted Signing / SignPath OSS / свой сертификат | стоимость, требования к организации, репутация SmartScreen |
| Кроссплатформенность | headless только MCP / полный порт с Avalonia / не делать | спрос; объём Windows-специфичного кода |

## 15. Как мерить успех

- **Экономия:** доля облачных токенов, ушедших на локальную модель (по `usage.jsonl`, с честным учётом детерминированных инструментов).
- **Отзывчивость:** медиана и p95 времени ответа `ask_files`/`find_context`, время ожидания в очереди GPU.
- **Надёжность:** доля вызовов с `isError`, число автоперезапусков llama-server, доля задач агента, слитых после проверки.
- **Установка:** доля пользователей, у которых мастер дошёл до «Готово» и IDE сделала первый вызов (по пакету диагностики и issues,
  без телеметрии).
- **Качество кода проекта:** тесты зелёные офлайн, покрытие не падает, 0 предупреждений анализаторов, `SecurityRegressionTests` растут
  вместе с поверхностью атаки.
