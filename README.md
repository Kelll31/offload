# Offload

**Локальная модель-помощник для Claude Code и других IDE.** Offload — приложение для Windows, которое живёт в трее, само ставит [llama.cpp](https://github.com/ggml-org/llama.cpp), скачивает модель для программирования, настраивает агент [OpenCode](https://opencode.ai) и подключается к вашим IDE как MCP-сервер. Claude Code (а также Cursor, VS Code, Codex, Gemini CLI и другие) получает набор инструментов, через которые может **делегировать рутинную работу бесплатной локальной модели** и тратить меньше облачных токенов.

Никакого Docker, WSL, Python и Node.js — один `Offload.exe`, всё ставится в профиль пользователя без прав администратора.

## Зачем это нужно

Самые дорогие токены в работе облачного агента — это:

1. **чтение больших файлов и логов** — каждый прочитанный файл остаётся в контексте и перечитывается на каждом следующем шаге;
2. **написание кода** — выходные токены в 5 раз дороже входных.

Offload забирает оба пункта на локальную модель:

- сервер **сам читает файлы** и отдаёт облачной модели только короткий ответ (вопрос по 2000 строкам кода стоит ~800 токенов вместо ~20 000);
- сервер **сам пишет файлы на диск** (тесты, DTO, заготовки, механические правки) и возвращает только сводку: сколько строк, прошла ли проверка командой;
- ответы компактные, с подписью, сколько облачных токенов удалось сэкономить. Общая статистика — в окне «Состояние».

Планирование, архитектура, сложная отладка и финальная проверка остаются за Claude — инструкции MCP-сервера прямо говорят ему, что делегировать, а что нет.

## Возможности

- **Мастер установки** (русский / English): определяет видеокарту, объём видеопамяти, драйвер и ОЗУ, подбирает сборку llama.cpp (CUDA 12/13, Vulkan, ROCm, SYCL, CPU) и модель, которая поместится.
- **Основная модель — Qwen3.8-27B** (лучшее качество кода среди локальных моделей): Q6 для 32+ ГБ видеопамяти, Q4 для 24 ГБ, IQ3 для 16 ГБ. Для карт слабее мастер предложит быстрые MoE (Qwen3.6-35B-A3B, Ornith) и 9B-модели.
- **Каталог актуальных моделей** (Qwen3.8/3.6/3.5, Ornith, gpt-oss, Qwen3-Coder-Next, Devstral и др.) с точными файлами, контрольными суммами SHA-256 и оценкой «поместится ли в видеопамять». MoE-модели автоматически выгружают часть экспертов в ОЗУ — 35B-модель работает даже на 8–12 ГБ видеопамяти.
- **Загрузка с докачкой** и проверкой контрольных сумм; можно добавить свой GGUF-файл.
- **llama-server под управлением трея**: автозапуск, перезапуск при сбое, выгрузка модели при простое, журнал, статус видеопамяти.
- **OpenCode** ставится автоматически и настраивается на локальную модель — для многошаговых правок агентом.
- **Подключение к IDE в один клик**: Claude Code, Claude Desktop, Cursor, VS Code (Copilot), Copilot CLI, Windsurf/Devin, Cline, Roo Code, Kilo Code, Zed, Gemini CLI, OpenAI Codex, JetBrains Junie, Continue, Visual Studio, Kiro, Trae, Qoder. Конфигурации правятся бережно (с резервной копией и сохранением комментариев).
- **Для Claude Code** дополнительно: навык (skill) с правилами делегирования, опциональное «строгое» правило, субагент и разрешения на инструменты чтения без подтверждения.
- **Безопасность**: сервер слушает только `127.0.0.1` с ключом API; MCP-инструменты не читают секреты (`.env`, ключи, сертификаты), пишут только внутри рабочей папки, проверочные команды — только из белого списка; любую правку можно откатить.
- Интерфейс трея и все окна — **на русском или английском** (переключается на лету), светлая/тёмная тема, готовые цветовые схемы и свой цвет акцента.

### Настройки программы

Раздел **«Настройки»** главного окна (или «Настройки…» в меню значка в трее):

- **Мастер настройки** — кнопка «Открыть мастер настройки» (то же — «Мастер настройки…» в меню трея): заново подобрать сборку llama.cpp и модель, переустановить компоненты, подключить IDE.
- **Внешний вид** — тема (как в Windows / светлая / тёмная), цветовая схема (синяя, бирюзовая, зелёная, фиолетовая, оранжевая, розовая, «Полночь», высокий контраст) или свой цвет акцента.
- **Язык / Language** — русский, English или как в Windows; меняется сразу, без перезапуска (выбор есть и на первом шаге мастера).
- **Модели** — папка для новых моделей (уже скачанные остаются на месте и продолжают работать).
- **Запуск и уведомления** — автозапуск с Windows, всплывающие уведомления, сворачивание в трей при закрытии окна.
- **Данные программы** — открыть папку данных и `config.json`.

## Инструменты MCP

24 инструмента в пяти группах. Всё, что можно сделать детерминированно (поиск, символы, диагностика, сканеры, патчи), сервер
делает сам, без модели и за секунды; локальная модель подключается там, где нужен «разум»: ответы по файлам, расширение запроса,
ревью, планы, разбор логов, написание кода.

**Контекст и навигация** — вместо десятков `Glob`/`Grep`/`Read` в облачном контексте:

| Инструмент | Что делает | Меняет файлы |
|---|---|---|
| `local_find_context` | Задача на естественном языке (в т. ч. по-русски) → сервер сам находит и ранжирует файлы, классы и методы, объясняет выбор и укладывает код в бюджет токенов; `mode=plan` добавляет план реализации | нет |
| `local_project_map` | Карта репозитория: проекты и связи, языки, точки входа, тестовые проекты, команды сборки/тестов; секции `routes`, `config`, `env`, `cli`, `ci`, `docker`, `rules` (CLAUDE.md/AGENTS.md…), `conventions` (стиль и соглашения) | нет |
| `local_search_code` | Поиск по тексту / regex / слову / имени файла с короткими сниппетами | нет |
| `local_symbols` | Outline, определение, ссылки, реализации, граф вызовов (callers/callees с глубиной), тесты для символа, публичный API, тело одной функции | нет |
| `local_ask_files` | Ответ на вопрос по файлам/папкам/маскам, которые сервер читает сам | нет |
| `local_git_history` | История файла/символа (`git log -L`), сводка blame по коммитам, связанные коммиты, changelog и заметки к релизу, «почему код такой» | нет |
| `local_memory` | Память проекта между сессиями: факты, решения (мини-ADR), соглашения | нет (хранится в папке данных Offload) |

**Проверки и анализ:**

| Инструмент | Что делает | Меняет файлы |
|---|---|---|
| `local_verify` | Сборка/тесты/линтер/форматирование (команда из белого списка или `kind` — определяется по проекту): в IDE — только итог, структурированные ошибки, кадры стека из кода проекта и разбор причины; полный лог — в `.offload/runs/` | нет (кроме артефактов сборки) |
| `local_diagnostics` | Ошибки компилятора/линтера как данные (MSBuild, tsc, eslint, gcc/clang, rustc, go, mypy/ruff) с символом и строкой кода; stack trace → файл, функция, строка | нет |
| `local_summarize_log` | Выжимка из большого лога; с `pattern` — поиск событий по id запроса/задачи без модели | нет |
| `local_impact` | Что затронет изменение: символы, вызывающие, связанные тесты, проекты; `run_tests` — прогон только связанных тестов | нет |
| `local_code_scan` | TODO, утёкшие секреты (значения маскируются), опасные API, async-проблемы, мёртвый код, дубли, сложность, горячие точки (сложность × частота изменений), сгенерированные файлы | нет |
| `local_review_diff` | Первичное ревью `git diff` / ветки | нет |
| `local_security_review` | Проверка безопасности только изменённого кода: правила + ревью моделью | нет |
| `local_dependency_check` | Пакеты: список, граф и «почему A зависит от B», лицензии (офлайн), неиспользуемые, устаревшие и уязвимые (через реестры) | нет |

**Написание кода** — всё со снимком для отката (`local_job action=revert`):

| Инструмент | Что делает | Меняет файлы |
|---|---|---|
| `local_solve` | Весь цикл одним вызовом: контекст → бриф агенту по виду задачи (feature / bug / refactor / tests / issue) → правки в git-песочнице → проверка с исправлениями → ревью → слияние → **доказательство результата** (файлы, проверка, диагностика, находки ревью, открытые вопросы) | да (после проверки) |
| `local_agent_task` | Задача локальному агенту OpenCode в **git-песочнице** с «бюджетом автономности» (`allowed_paths`, `max_files`, время, раунды исправлений, ревью перед слиянием); может работать в фоне | да (после проверки) |
| `local_apply_patch` | Unified diff атомарно: все хунки сверяются заранее (устойчиво к сдвигу строк и CRLF), кодировка сохраняется, проверка и автооткат | да |
| `local_refactor` | `rename` символа по всем ссылкам (с переименованием файла, проверкой конфликтов и автооткатом); `extract_method` / `extract_class` / `move_symbol` / `inline` / `change_signature` — агентом в песочнице | да |
| `local_write_file` | Новый файл по спецификации (тесты, DTO, фикстуры, документация) + проверочная команда | да |
| `local_edit_files` | Механическая правка списка файлов + проверка | да |
| `local_commit_message` | Сообщение коммита, описание PR (`kind=pr`) или план разбиения большого diff на коммиты (`kind=split`) | нет |

**Служебные:** `local_job` — список задач, статус (с ожиданием фоновой), diff, слияние/удаление песочницы, отмена, откат;
`local_status` — состояние модели, скорость, экономия токенов.

В Claude Code инструменты называются `mcp__offload__<имя>`. Пример запроса: *«используй offload: найди, где считается скидка,
и почини баг с округлением — с тестом»* → `local_find_context` + `local_solve kind=bug`.

### Git-песочница локального агента

`local_agent_task` не трогает ваши файлы, пока агент работает: рабочая папка (включая незакоммиченные и новые файлы, кроме секретов)
фиксируется во временном индексе как коммит-снимок, от него создаётся `git worktree` в `%LOCALAPPDATA%\Offload\sandboxes\`.
Ваш индекс, HEAD и ветки не меняются. Если проект не под git, Offload заводит скрытый «теневой» репозиторий в своей папке данных —
в самом проекте `.git` не появляется. Изменения переносятся в проект, только если проверка прошла и патч применяется без конфликтов;
перед записью делается снимок файлов, так что `local_job action=revert` отменяет слияние. Секреты, символические ссылки и файлы
вне рабочей папки (и вне `allowed_paths`) из песочницы не переносятся; слияние блокируется, если проверка не прошла, изменено
больше `max_files` файлов или ревью локальной модели нашло critical/high-проблемы — тогда работа ждёт решения на ветке
(`local_job action=diff` → `merge` / `discard`).

### Как устроены поиск и навигация

Индекс кода строится на лету (с учётом `.gitignore`, без секретов и двоичных файлов) и кэшируется в процессе MCP-сервера по
размеру и времени изменения файлов, поэтому повторные вызовы в сессии быстрые. Символы разбираются эвристически (регулярные
выражения + подсчёт скобок, для Python — отступы) для C#, TypeScript/JavaScript, Python, Go, Java, Kotlin, Rust, C/C++, Pascal/Delphi,
PHP, Ruby и Swift — без компилятора и language server. Ссылки и граф вызовов текстовые: одноимённые члены разных типов не различаются,
поэтому результаты стоит перепроверять перед важными решениями (инструменты прямо это пишут).

### Слэш-команды (MCP prompts)

Сервер публикует готовые сценарии; в Claude Code они доступны как `/mcp__offload__<имя>`:

| Команда | Что делает |
|---|---|
| `delegate` | Передать задачу программирования локальному агенту (песочница + проверка) и проверить результат |
| `review` | Двухпроходное ревью: локальная модель находит, Claude подтверждает каждую находку |
| `tests` | Тесты для файла силами локальной модели до зелёного прогона |
| `fix_build` | Прогнать сборку/тесты, разобрать ошибки и починить (механическое — агенту) |
| `explain` | Объяснить код по путям/маскам, не читая его в контекст |
| `solve` | Решить задачу целиком локальным конвейером и проверить доказательство результата |
| `context` | Собрать контекст под задачу: память проекта → `local_find_context` → символы |
| `security` | Проверка безопасности текущих изменений (правила + модель), Claude подтверждает находки |

## Установка

1. Скачайте `Offload-Setup-<версия>.exe` (или просто `Offload.exe`) со страницы [Releases](https://github.com/Kelll31/offload/releases).
2. Запустите — откроется мастер настройки. Он предложит сборку llama.cpp и модель под ваше железо, скачает всё нужное и подключит найденные IDE.
3. Перезапустите Claude Code (или выполните `/mcp`) — появится сервер `offload`.

Требования: Windows 10 1809+ / Windows 11 x64, желательно видеокарта NVIDIA/AMD/Intel с 8+ ГБ видеопамяти (работает и на процессоре, но медленно), 10–30 ГБ свободного места под модель. Для сборок llama.cpp нужен Visual C++ Redistributable — мастер установит его сам (потребуется подтверждение UAC).

### Ручное подключение к любой IDE

```json
{
  "mcpServers": {
    "offload": {
      "command": "C:\\Users\\<вы>\\AppData\\Local\\Programs\\Offload\\Offload.exe",
      "args": ["--mcp"]
    }
  }
}
```

Точный путь и готовый JSON есть на вкладке «Интеграции» — кнопка «Копировать».

## Где что лежит

| Путь | Что |
|---|---|
| `%LOCALAPPDATA%\Programs\Offload\Offload.exe` | программа (при установке через установщик) |
| `%LOCALAPPDATA%\Offload\config.json` | настройки |
| `%LOCALAPPDATA%\Offload\llama.cpp\` | сборка llama.cpp |
| `%LOCALAPPDATA%\Offload\models\` | модели GGUF (папку можно сменить) |
| `%LOCALAPPDATA%\Offload\opencode\` | OpenCode и его изолированная конфигурация |
| `%LOCALAPPDATA%\Offload\logs\` | журналы приложения, llama-server и MCP |
| `%LOCALAPPDATA%\Offload\usage.jsonl` | статистика обращений и экономии |
| `%LOCALAPPDATA%\Offload\jobs\` | снимки задач записи/правки для отката (хранятся `JobRetentionDays` дней) |
| `%LOCALAPPDATA%\Offload\sandboxes\` | git-песочницы локального агента (worktree) и теневые репозитории для проектов без git |
| `%LOCALAPPDATA%\Offload\memory\` | память проектов (`local_memory`) |
| `<проект>\.offload\runs\` | полные логи `local_verify` / `local_diagnostics` (папка сама себя исключает из git) |

Переменная окружения `OFFLOAD_HOME` переносит папку данных (портативный режим).

## Сборка из исходников

Нужен [.NET SDK 10](https://dotnet.microsoft.com/download/dotnet/10.0).

```powershell
.\scripts\build.ps1              # тесты + publish\Offload.exe (самодостаточный, ~60 МБ)
.\scripts\build.ps1 -Installer   # + установщик dist\Offload-Setup-<версия>.exe (нужен Inno Setup 6 или 7)
```

Проверка MCP-сервера без IDE:

```powershell
node scripts\mcp-smoke.mjs .\publish\Offload.exe local_status '{}'
```

### Структура решения

| Проект | Назначение |
|---|---|
| `Offload.Core` | пути, настройки, журнал, загрузчик с докачкой, определение железа, IPC, статистика |
| `Offload.Llama` | релизы llama.cpp, установка, управление llama-server, клиент OpenAI-совместимого API |
| `Offload.Models` | каталог моделей, оценка видеопамяти, Hugging Face, чтение GGUF |
| `Offload.OpenCode` | установка и изолированная настройка OpenCode, неинтерактивный запуск агента |
| `Offload.Integrations` | регистрация MCP-сервера в IDE, навык и разрешения Claude Code |
| `Offload.Mcp` | stdio MCP-сервер (`Offload.exe --mcp`) и инструменты делегирования |
| `Offload.App` | трей, панель управления, мастер настройки (WinForms, русский интерфейс) |

## Удаление

Удалите программу через «Параметры → Приложения». Деинсталлятор отключит Offload от всех IDE и спросит, удалять ли скачанные модели.
