# Удалённый каталог моделей

Offload раз в сутки проверяет `catalog/catalog.json` в ветке `main` этого репозитория
(`https://raw.githubusercontent.com/Kelll31/offload/main/catalog/catalog.json`; адрес меняется параметром
`network.catalogUrl` в `config.json`) и лежащую рядом подпись `catalog.json.sig`. Новые модели выходят чаще релизов
Offload — так они доходят до пользователей без обновления программы.

Каталог применяется, только если:

1. подпись Ed25519 точных байтов файла сходится с открытым ключом, зашитым в сборку
   (`RemoteCatalog.PublicKeyBase64` в `src/Offload.Models/RemoteCatalog.cs`);
2. каталог проходит те же проверки, что и встроенный (`ModelCatalog.ParseDocument`);
3. его `version` больше версии действующего каталога (встроенного или ранее скачанного) — откат не принимается;
4. его `version` не меньше наибольшей когда-либо принятой версии (`catalog\max-version` в папке данных): старый
   подписанный каталог не примется и после удаления или порчи кэша, и с другого `network.catalogUrl`;
5. если в нём есть поле `"expires"` (дата ISO 8601, например `"2027-03-31T00:00:00Z"`), эта дата ещё не наступила.

Иначе, а также без сети, действует прежний каталог. Скачанный каталог хранится в `%LOCALAPPDATA%\Offload\catalog\`
одним файлом `catalog.signed.json` (подпись и точные байты каталога в base64, одна атомарная замена — трей и MCP-процесс
не увидят подпись от одного каталога с другим) и при каждом запуске заново проверяется по подписи и сроку. Прежний формат
(`catalog.json` + `catalog.json.sig`) ещё читается и заменяется новым при следующем обновлении. Пока открытый ключ в коде
не задан, удалённый каталог отключён.

### Защита от отката и поле `expires`

`max-version` защищает, пока цела папка данных. После её полной очистки (или на новом компьютере) нижняя граница — версия
встроенного каталога, и злоумышленник, способный подменить ответ сервера каталога (или адрес `network.catalogUrl`),
может подсунуть любой старый, но подписанный каталог новее встроенного. Это закрывает `"expires"`: подпись покрывает поле,
и каталог с истёкшим сроком не принимается ни с сервера, ни из кэша. Поле необязательное; с ним каталог нужно
переподписывать (с новой `version`) до истечения срока — иначе клиенты вернутся к встроенному каталогу. Разумный срок —
3–6 месяцев.

## Публикация (вручную, мейнтейнер)

1. Однократно создать ключ и вставить открытый ключ в код:
   `.\scripts\sign-catalog.ps1 -GenerateKey -Key D:\keys\offload-catalog.pem` → base64 в `RemoteCatalog.PublicKeyBase64`.
   Закрытый ключ в репозиторий не попадает.
2. Скопировать `src/Offload.Models/catalog.json` в `catalog/catalog.json` (формат тот же, комментарии допустимы),
   увеличить `"version"` (ГГГГММДДNN) — и во встроенном каталоге тоже, чтобы следующий релиз не был «старше».
3. Подписать: `.\scripts\sign-catalog.ps1 -Key D:\keys\offload-catalog.pem` → `catalog/catalog.json.sig`
   (скрипт спросит пароль ключа: `-GenerateKey` по умолчанию шифрует ключ AES-256-CBC; `-NoEncryption` — только с
   предупреждением и для ключа на зашифрованном или аппаратном носителе). Если используется `"expires"` — сдвинуть срок.
4. Закоммитить `catalog.json` и `catalog.json.sig` одним коммитом. После подписи файл не редактировать
   (`.gitattributes` здесь отключает нормализацию концов строк, чтобы байты на GitHub совпадали с подписанными).

Поля, которых нет в текущей версии Offload, пропускаются: более новый каталог читается и прежними версиями.
